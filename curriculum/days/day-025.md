# Day 25: Exceptions

**Teach:** Distinguish expected invalid input from unexpected failures; model a useful error boundary and avoid swallowing exceptions.
**Learn:** `try`/`catch`/`finally`, checked and unchecked exceptions, custom exceptions, and meaningful messages.
**Build:** Report missing books and invalid checkout operations with clear domain errors; keep console recovery at the input boundary.
**Interview:** What is the difference between checked and unchecked exceptions, and when would you use each?
**DSA:** Find the insertion position for a target in a sorted array using binary search.
**Checkpoint:** Student handles an expected error without hiding programming defects.
