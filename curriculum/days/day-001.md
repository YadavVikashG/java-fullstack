# Day 1: Your First Java Program

**Time:** 2-3 hours  
**Outcome:** Compile and run a Java program, explain the basic execution path, and complete a first array scan.

## 1. Start the lesson

Ask the student: "What do you think happens between writing Java code and seeing text in the terminal?" Let them guess before explaining. Keep the first explanation short:

- **Source code:** the `.java` file a developer writes.
- **Compiler (`javac`):** translates source code into Java bytecode (`.class` files).
- **JVM:** runs that bytecode on the current operating system and hardware.
- **JDK:** the development kit containing tools such as `javac` and the runtime needed to run Java programs.

Draw: `Day1.java -> javac -> Day1.class (bytecode) -> JVM -> output`.

## 2. Check the setup

Install a JDK 21 or newer. In a terminal, run:

```sh
java -version
javac -version
```

Both commands should print a version. If `javac` is not found, the JDK is missing or its `bin` directory is not on `PATH`; resolve that before continuing.

## 3. Read and run the code

Open [Day1.java](../../examples/day-001/Day1.java). Read it once together before running it. Point out that `Day1` is the class name, `main` is where this program starts, and each statement ends with a semicolon.

Compile and run from the workspace root:

```sh
mkdir -p /tmp/day1-out
javac -d /tmp/day1-out examples/day-001/Day1.java
java -cp /tmp/day1-out Day1
```

Expected output:

```text
Student: Alex
Goal: Become a Java full-stack developer
Fun fact: I enjoy solving puzzles
Maximum value: 9
```

Ask the student to change the profile values, predict the output, run it again, and explain what changed. Then briefly break the code (for example, remove a semicolon), compile, read the error, and repair it. This makes compiler messages part of the normal workflow.

## 4. Interview practice

**Question:** What are the JDK, JVM, and bytecode, and how do they relate when a Java program runs?

**Model answer:** I write Java source in a `.java` file. The JDK's compiler, `javac`, compiles it into bytecode in a `.class` file. The JVM for the target platform loads and runs that bytecode. The JDK includes the development tools; the JVM is the runtime that executes the program.

Have the student explain it back without memorizing the wording. Follow up: "Which command compiles the source? Which command starts the program?"

## 5. DSA practice: Find the maximum

**Problem:** Given a non-empty integer array, return its largest value. For `[4, -2, 9, 3]`, the answer is `9`.

Ask the student to try first. Hint 1: keep the largest value seen so far. Hint 2: initialize it to the first array element, then inspect each remaining element. Do not initialize it to zero; the array could contain only negative numbers.

The solution is included as `findMaximum` in [Day1.java](../../examples/day-001/Day1.java). Trace it on paper:

| Value read | Maximum so far |
| --- | --- |
| Start at `4` | `4` |
| `-2` | `4` |
| `9` | `9` |
| `3` | `9` |

It visits each element once: $O(n)$ time and $O(1)$ extra space. The method rejects an empty array because no maximum exists; discuss that precondition before looking at the guard in code.

**Stretch:** Change the input to `[-8, -3, -11]`. Then write a second method that returns both the minimum and maximum in one pass.

## 6. Teaching sequence and checkpoint

Use this rhythm: ask and listen (5 min), explain the execution path (10 min), type and predict together (20 min), student edits and debugs (20 min), interview question (10 min), DSA attempt and hints (25 min), recap (5 min). Adjust the pace to the learner; setup trouble is not a measure of programming ability.

The student is ready to move on when they can compile and run the program from the terminal, describe what `main` does, explain JDK/JVM/bytecode in their own words, and walk through the maximum scan. Homework: change the profile, try the all-negative DSA case, commit the work, and write down one compiler message and how they fixed it.
