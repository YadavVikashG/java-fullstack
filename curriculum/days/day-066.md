# Day 66: Transactions and Concurrency

**Teach:** Walk through two users updating the same record; distinguish atomicity from isolation and identify lost-update risk.
**Learn:** `@Transactional`, propagation basics, optimistic locking, version columns, and transaction boundaries.
**Build:** Protect a concurrent update with optimistic locking and return a clear conflict when stale data is submitted.
**Interview:** What is optimistic locking, and when is it preferable to pessimistic locking?
**DSA:** Solve the 0/1 knapsack problem for a small input and explain the DP state.
**Checkpoint:** A test demonstrates that conflicting updates do not silently overwrite each other.
