# Day 64: Schema Migrations

**Teach:** Explain why production schema changes need a history and why an ORM should not silently rewrite important schemas.
**Learn:** Flyway or Liquibase concepts, versioned migrations, forward-only change habits, and repeatable local setup.
**Build:** Add a migration for a new task field and verify a clean database can be created from migration history.
**Interview:** Why use database migrations instead of relying on automatic schema creation in production?
**DSA:** Solve coin change for minimum coins with dynamic programming; define unreachable and base cases.
**Checkpoint:** Fresh database and existing database both reach the same schema using versioned migrations.
